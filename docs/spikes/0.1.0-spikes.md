# 0.1.0 spikes (2026-11-06)
These answer the "verify in 0.1.0" items in `VISUS-ARCHITECTURE.md`.

## 1. Does FML 47 honour `provides` in mods.toml? No.
- FML 47 (`fmlloader-1.20.1-47.3.0`) reads `provides` only for JPMS service descriptors (`ModJarMetadata`, `ModDirTransformerDiscoverer`). `ModInfo` never reads a mods.toml `provides` key.
- So `provides=["iris"]` is a no-op on Forge 1.20.1, exactly as it is in Oculus. `ModList.isLoaded("iris")` is false under both. No dependent in the census relies on it.
- We keep the key anyway. It costs nothing, and Sinytra Connector or future loaders may read it.
- **Consequence:** the `oculus` alias mod entry (A§4.1) is the mechanism that matters.

## 2. Does SecureJar load multi-release jars? Yes.
- `securejarhandler 2.1.10`, which Forge 47 uses, reads the `Multi-Release` manifest attribute in `cpw.mods.jarhandling.impl.Jar`. It resolves `META-INF/versions/<n>/` against `Runtime.version()`.
- So a multi-release jar is an option for Java 21+/22+ code paths (for example the FFM API).
- **Still to do before using it:** a boot test on Java 17, 21 and 25 with one versioned class.

## 3. Upstream Iris features that Oculus 1.8.0 lacks
Compared against upstream Iris branch `26.1` @ `bff1e69` (2026-09-15). The comparison is regex-based, so check each item before backporting it in 0.8.

| Kind | Upstream only | Notes |
|---|---|---|
| Feature flags (`iris.features.required/optional`) | `CAN_DISABLE_WEATHER`, `FADE_VARIABLE`, `TEXTURE_FILTERING` | Packs that *require* one of these refuse to load on Oculus and Visus today |
| Standard macros | `IRIS_HAS_CONNECTED_TEXTURES`, `IRIS_HAS_TRANSLUCENCY_SORTING`, `IRIS_REQUIRES_SEPARATE_ENTITY_DRAWS`, `IRIS_TAG_SUPPORT`, `DISTANT_HORIZONS_TEXTURES`, `MAX_COLOR_BUFFERS`, `MC_MIPMAP_LEVEL`, `MC_GL_RENDERER_APPLE`, `ALLOWS_UNKNOWN_SHADERS`, `IRIS_VERSION`* | *`IRIS_VERSION` may simply be defined differently in 1.8.0; check. `IS_MONOCLE` is upstream's own and not relevant. |
| Oculus upstream, post-1.8.0 | `IS_OCULUS` (#806) | Planned for 0.2.0 (see `docs/CHANGES-FROM-OCULUS.md`) |

Some of these describe capabilities Oculus doesn't have; for example, upstream only defines `IRIS_HAS_TRANSLUCENCY_SORTING` when it really sorts translucency. A macro may only be defined once Visus actually provides the behaviour behind it.
